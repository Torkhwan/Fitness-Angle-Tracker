# FAT: Fitness Angle Tracker

โครงงานวิชา Linear Algebra กลุ่มแมวส้ม & โอริโอ้

ตรวจท่าออกกำลังกาย 3 ท่า (Squat / Push-up / Lunge) จากภาพถ่ายด้านข้าง
MediaPipe ใช้แค่ดึงพิกัดข้อต่อ ส่วนการคำนวณเวกเตอร์และเมทริกซ์ทั้งหมดเขียนเอง

```
ภาพ → พิกัดข้อต่อ → normalize ด้วยเมทริกซ์ M → มุม 3 ค่า → เทียบท่าต้นแบบ → คำแนะนำ + เส้นท่าที่ถูก
        (งาน D)          (งาน A)               (งาน B)      (งาน C)            (งาน C, D)
```

## 6. วิธีทำงานกับ Git (GitHub Desktop)

หลักที่ต้องจำ 3 ข้อ

1. ทำงานใน **branch ของตัวเองเท่านั้น** ไม่ commit ใน `main`
2. **ก่อนเริ่มทำงานทุกครั้ง** กด Fetch origin แล้ว Update from main
3. แก้เฉพาะไฟล์ของงานตัวเอง

### 6.1 ครั้งแรก (ทำครั้งเดียว)

**รับคำเชิญ:** เปิดอีเมลจาก GitHub แล้วกด Accept invitation ถ้าไม่รับจะ push ไม่ได้

**ดาวน์โหลดโครงงานลงเครื่อง**

1. เปิด GitHub Desktop → เมนู File → Clone repository
2. แท็บ GitHub.com → เลือก repo ของโครงงาน
3. Local path เลือกที่เก็บที่หาง่าย เช่น Desktop → กด Clone

**สร้าง branch ของตัวเอง**

1. ดูแถบบน ช่องกลางเขียนว่า Current branch `main` → กดที่ช่องนั้น
2. กด New branch
3. Name ใส่ชื่อ branch ของตัวเองตามตารางข้อ 1 (`Praw` / `Tonlew` / `tonkla` / `Jennie`) สะกดให้ตรง
4. กด Create branch
5. กด **Publish branch** (ปุ่มสีน้ำเงินขวาบน) เพื่อให้ branch ขึ้นไปอยู่บน GitHub

เสร็จแล้วช่อง Current branch ต้องเป็นชื่อตัวเอง

**เปิดใน VS Code:** เมนู Repository → Open in Visual Studio Code

### 6.2 ก่อนเริ่มทำงานทุกครั้ง

ทำ 3 ขั้นนี้ก่อนพิมพ์โค้ดบรรทัดแรก ไม่งั้นจะทำงานบนไฟล์เก่าและชนกับเพื่อนตอนส่ง

| ขั้น | ทำอะไร | เพื่ออะไร |
|---|---|---|
| 1 | ดูช่อง **Current branch** ต้องเป็นชื่อตัวเอง ถ้าเป็น `main` ให้กดแล้วเลือก branch ของตัวเอง | กัน commit ผิดที่ |
| 2 | กด **Fetch origin** (ขวาบน) ถ้าปุ่มเปลี่ยนเป็น **Pull origin** ให้กดอีกครั้ง | ดึงข้อมูลล่าสุดจาก GitHub |
| 3 | เมนู **Branch → Update from main** ถ้าปุ่มขวาบนขึ้น **Push origin** ให้กด | เอางานที่เพื่อน merge แล้วเข้ามาใน branch เรา |

ถ้าขั้น 3 ขึ้นว่า already up to date แปลว่าไม่มีอะไรใหม่ ทำงานต่อได้เลย

### 6.3 ระหว่างทำงาน: commit และ push

1. เขียนโค้ดในไฟล์ของตัวเอง แล้ว **บันทึกไฟล์** (`Ctrl + S`)
2. รันทดสอบใน terminal (ข้อ 5)
3. กลับมาที่ GitHub Desktop แท็บ **Changes** (ซ้ายบน) จะเห็นรายชื่อไฟล์ที่แก้
4. **ตรวจรายชื่อไฟล์** ต้องมีแต่ไฟล์ของงานตัวเอง
   - มีไฟล์อื่นโผล่มา (เช่น ไฟล์ของเพื่อน, `test.csv`, `clean_log.csv`, `templates.json`) → คลิกขวาที่ไฟล์นั้น → Discard changes
5. ช่อง **Summary** (ซ้ายล่าง) พิมพ์สั้น ๆ ว่าทำอะไร เช่น `add norm and angle_between`
6. ดูปุ่มสีน้ำเงินต้องเขียนว่า **Commit to <ชื่อตัวเอง>** ถ้าเขียนว่า Commit to main **อย่ากด** ให้ไปดูข้อ 6.5
7. กด Commit
8. กด **Push origin** (ขวาบน)

commit = บันทึกลงเครื่องตัวเอง, push = ส่งขึ้น GitHub ต้องทำทั้งสองอย่างเพื่อนถึงจะเห็น

commit บ่อย ๆ ทีละ 1-3 ฟังก์ชัน ไม่ต้องรอเสร็จทั้งไฟล์ และ push ทุกครั้งก่อนเลิกทำงาน

### 6.4 ส่งงานเข้า main (pull request)

ทำเมื่อทดสอบผ่านครบตามหัวข้อ "เสร็จเมื่อ" ในเอกสารงานตัวเอง

1. ทำข้อ 6.2 อีกรอบ (Fetch → Update from main) แล้วรันทดสอบซ้ำ
2. Push origin ให้เรียบร้อย
3. เมนู **Branch → Create pull request** → เบราว์เซอร์จะเปิดขึ้น
4. ดูบรรทัดบนต้องเป็น `base: main` ← `compare: <ชื่อตัวเอง>`
5. ใส่ชื่อเรื่อง เช่น `งาน B: vector.py` → กด **Create pull request**
6. ส่งลิงก์ในกลุ่ม ให้เพื่อน 1 คนเปิดดู แล้วกด **Merge pull request → Confirm merge**
7. หน้าเว็บจะมีปุ่ม Delete branch **ไม่ต้องกด** เพราะยังต้องใช้ branch เดิมทำงานต่อ
8. แจ้งในกลุ่มว่า merge แล้ว ทุกคนทำข้อ 6.2 เพื่อรับงานใหม่

ส่งได้หลายรอบ เช่น งาน B ส่ง `vector.py` ก่อน แล้วค่อยส่ง `features.py`

### 6.5 ถ้าเกิดปัญหา

| อาการ | วิธีแก้ |
|---|---|
| ปุ่มเขียนว่า Commit to main | ยังไม่ต้อง commit กดช่อง Current branch → เลือก branch ตัวเอง → มีหน้าต่างถาม ให้เลือก **Bring my changes to <ชื่อตัวเอง>** → Switch branch |
| commit ใน `main` ไปแล้ว แต่ยังไม่ push | แท็บ History → คลิกขวา commit บนสุด → Undo commit → แล้วทำตามแถวบน |
| commit ใน `main` และ push ไปแล้ว | หยุด ไม่ต้องแก้เอง แจ้งในกลุ่มทันที |
| Push ไม่ผ่าน ขึ้นว่ามี commit ใหม่กว่าบน remote | กด Fetch origin → Pull origin → แล้ว Push อีกครั้ง |
| ขึ้นหน้าต่าง Resolve conflicts | แปลว่ามีคนแก้บรรทัดเดียวกัน อย่ากดเลือกมั่ว ถ่ายหน้าจอส่งในกลุ่ม |
| ไม่เห็นงานของเพื่อนทั้งที่ merge แล้ว | ยังไม่ได้ทำข้อ 6.2 |
| แก้ไฟล์แล้วแท็บ Changes ว่าง | ยังไม่ได้บันทึกไฟล์ใน VS Code (`Ctrl + S`) หรือเปิดโฟลเดอร์ผิดที่ |
| แก้ไฟล์พังจนอยากเริ่มใหม่ | แท็บ Changes → คลิกขวาที่ไฟล์ → Discard changes (กลับไปเหมือน commit ล่าสุด) |

ไม่แน่ใจตรงไหน ถามในกลุ่มก่อนกด Push เพราะสิ่งที่ยังไม่ push แก้ไขได้ง่ายเสมอ
